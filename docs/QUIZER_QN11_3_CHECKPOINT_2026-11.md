## Changes implemented

1. **`js/services/import-resume.js`** — strict 1–20 record planning (default request cap 650,000 UTF-8 bytes), stable-key filtering against the server ledger, SHA-256 source/image fingerprints, and 24-hour *sessionStorage-only* recovery metadata scoped by teacher UID and import mode. Never stores raw question/answer text, source bytes or image bytes. The existing sign-out cleanup removes `mathquiz.recovery.*`.
2. **`js/pages/quiz-editor.js`** — replaces one `importProblemBatch` call per question with bounded multi-item calls; uses stable per-chunk request IDs; saves source/image IDs and job creation nonce after upload; reselecting identical source/images after page reload resumes from an authenticated server checkpoint rather than a stale browser counter. Does not reupload already referenced assets. Resumes after lost acknowledgments and checks exact distinct server keys before `finishImportJob`. Preserves the existing QN12.2 accessible progress and retry status. If browser session storage was cleared/unavailable or images were changed, automatic recovery is not guaranteed; earlier incomplete jobs stay non-public and are not deleted.
3. **`functions/src/api/quizzes.js`** — existing Firebase callable dispatcher gains a narrowly scoped `getImportCheckpoint` teacher action (no new HTTP service) returning only the authorized user's import job source reference, source fingerprint, status, completion/result and distinct item keys; no protected question/grading content. The existing `createImportJob` accepts optional SHA-256 source fingerprint and persists an empty key ledger. The existing `importProblemBatch` rejects duplicate item keys, checks mapping/ledger integrity and persists `importedKeys` and `processed` in the same Firestore transaction as problem and mapping writes; historical jobs missing the ledger fall back to an owner-authorized mapping inventory. Existing Firestore-only route remains active on the unmerged branch; this does not switch the bank source of truth to Neon.
4. **`functions/src/neon/import-coordinator.js`** — independently staged, **default-OFF** durable Firestore `prepare` / `recordEffect` / `finalize` import orchestration. Private `jobs/{jobId}/importOperations/{requestId}` records capture only operation digest, item hashes/points and returned SQL IDs. Firebase transactions enforce verified role, job ownership, action/request binding, bounded fencing leases and exact SQL mapping parity, then atomically commit per-item Firestore job mappings/draft refs with distinct-count progress. SQL itself happens outside these transactions, via the QN11.2 gateway; no active Firebase router wiring.
5. **`functions/src/neon/orchestrator.js`** — passes hash-only expected import item summary and job ID to the staged coordinator. **`functions/src/neon/action-gateway.js`** normalizes trusted Firebase `job.input.sourceAssetId` for the staged Neon writer instead of accepting any caller-supplied owner/source.
6. **Tests:** `tests/unit/qn11-3-import-resume.test.mjs` covers 10/100/500 imports, size-based splitting, duplicate keys, missing key resume, exact text/image fingerprints and privacy-scoped recovery; `tests/integration/qn11-3-import-coordinator.test.mjs` exercises real **Firebase emulator** transactions (staged writer is synthetic) for 20/100-item commits, replay, role revocation, competing batch fencing and non-public drafts. Existing QN8 writer's 100/500 SQL mock/receipt/rollback regressions remain.

## Safety, consistency and known limitations

- **Not a production cutover.** No actual Quizer or Mimo PostgreSQL connection, SQL DDL or schema migration; no OAuth/API secrets; no production Firebase resources; no merges or deployments. New SQL problem writes remain gated behind the QN11.2 default-OFF SQL/orchestrator modules. The existing legacy Firestore teacher bank, publish and student paths remain authoritative.
- **Exactly-once logical import keys** rely on Firebase transactional mappings for the active path; staged Neon writer uses SQL import receipts and deterministic IDs, with a fenced Firebase coordinator for cross-store mapping. PostgreSQL–Firestore atomicity is impossible. SQL committed but not acknowledged may be re-played using unchanged key/hash; the old published quiz and all pinned attempts stay unaffected. There is no scheduled reconciliation worker in QN11.3; replay is caller/worker driven and will need full fault-injection in QN11.6.
- Client's source fingerprint is an *equality aid* for reload, not trusted verification of Storage bytes. Firebase owner/status checks and server-side SQL asset-verification callbacks remain essential. Browser recovery intentionally requires the exact source and images to be reselected after reload, rather than retaining protected text indefinitely.
- A bank-only import does not create a quiz. Incomplete quiz imports cannot appear in the public quiz catalog; the private draft root is created only by explicit `finishImportJob`. Metadata-only edits remain independent of the import path. The new staged Neon coordinator is unmounted and must not be wired into Firestore transaction callbacks.
- Import operation leases are checked at effect recording and again at Firestore finalization. An expired fence cannot attach SQL rows; replay creates a fresh token and can safely reuse immutable SQL item receipts. This is verified in the Firebase emulator.
- A future QN11.4 or QN11.6 gate must reconcile old mixed-source references, real Neon receipt parity, source provenance, retained assets, old quizzes, and comprehensive cross-store rollback. Restrictive quizer_app SQL role and disposable real PostgreSQL trial require separate approval.
