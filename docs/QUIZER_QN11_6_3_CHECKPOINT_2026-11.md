## Added / modified

1. **Private attempt/result image scope:** `functions/src/bundles/private-image-scope.js` adds concrete Firestore transaction read/role checks for the verified Firebase caller, saved attempt ownership or authorized teacher/admin, deadline, frozen status, pinned revision, no-back frontier, and score/solution-release policy. `private-integration.js` rechecks the same scope after external protected-bundle reads and before signing. `private-image-signer.js` requires a retained published-revision reference for private attempt/result images, validates only ready generation-pinned image objects under `assets/<owner>/<assetId>/image.<ext>`, and uses per-image **two-minute** HTTPS links. It refuses source/ZIP/bundle URLs, download tokens and unready records. Student no-back, result and staff permissions remain distinct.
2. **Author image provenance:** `private-author-image-scope.js` exposes trusted, verified QN11.4 Neon problem and hybrid draft image authorization with required owner/role checks, exact problem revision reads, 1–20 slot batches (up to 500 slots) and final draft-version recheck. Unknown provenance and Neon failures do **not** convert into legacy access. `getAssetLinks` routes `problem`/`quiz_draft` through these **injected trusted QN11.4 ports**, and routes historical `firestore_legacy`, `source`, and `owned_upload` contexts through the existing Firestore authorizer. **Concrete live hybrid-provenance registry and QN11.4 draft ports still require QN11.6.4 integration; with none provided, private author image scopes fail closed.**
3. **Protected private-published image retention:** `private-asset-retention.js` scans the trusted, validated immutable bundle image bindings, deduplicates/sorts at most **2,000** image IDs and retains refs under the exact `quizzes/<quizId>/revisions/<revisionId>` target in **20-image Firestore-only transactions**. Each batch verifies the current publication lease, owner, job input and pinned manifest. Per-batch receipts and an atomic completion marker permit safe retries without double-incrementing reference counts. The staged `publish-writer.js` now invokes retention after its verified create-only private bundle write and **before** publication activation. `firestore-publication-store.js` verifies the retention marker/hash/count in the activation transaction. This protects historical revision images without putting Storage/Neon calls inside Firestore transaction retries. Failed publication may deliberately leave conservative retained refs; no destructive cleanup is attempted. The existing live publisher is not modified.
4. **Owner-only export job state:** `private-export-store.js` implements a verified Firestore export preflight, lease and owner rechecks, pinned ready-bundle manifest, atomic job completion with result/metadata/audit, exact duplicate completion replay and signed-link access limited to the authorized teacher/admin. It adapts the actual stored `export_quiz` schema: `targetId`, `input.revisionId`, `requestedBy`, `leaseOwner`; no client-asserted job owner. Historical completed ZIPs continue to use the old link path. `export_results` CSV and legacy export jobs remain on the existing worker.
5. **ZIP and images:** `private-export-asset-reader.js` reads only **ready, retained, generation-pinned** image objects, checking Firestore reference records and SHA-256 of exact Storage bytes. `private-zip-worker.js` builds a real compressed, deterministic ZIP with `quiz.json` and `images/<id>.<ext>`, keeping the legacy `math-quiz-backup` schema and per-item IDs, problem revisions and points. Grading keys are present inside the **owner-only ZIP**, never returned to students. An uploaded ZIP must be privately stored, bounded and read back with matching SHA/byte size before the job is marked successful. A Storage 412 or lost acknowledgment is accepted only when the existing object matches the regenerated bytes exactly; otherwise it fails closed. The worker never signs published-bundle objects and never marks a failed/expired lease complete.
6. **Strict storage policy:** `private-zip-storage.js` uses create-only GCS precondition `ifGenerationMatch:0`, exact quiz/job-scoped `exports/<owner>/<job>/<quiz>-<job>.zip` paths, content type `application/zip`, private/no-store cache policy, 128 MiB ZIP bound, generation-pinned readback and SHA validation. Owner-only signed URLs are capped at 120 seconds, with no Firebase download token. The ZIP worker also bounds total uncompressed image payload at **80 MiB**. Any oversized backup fails closed.
7. **Safe publication metadata:** `private-start-export.js` now checks export source revision hash/generation against the trusted job manifest and supplies private ZIP metadata **without** the internal `published-bundles/` Storage path. It remains a server-only source. `private-staging-runtime.js` assembles the Firebase image scope, reference retention, private ZIP Storage, verified image reader, job/export-link ports and worker into the existing default-OFF factory; **neither the active Firebase router nor worker imports this factory**.
8. **Action compatibility:** `private-integration.js` extends the staged existing API v2 actions `getAssetLinks` and `getExportLink`, plus worker-only `exportJob`. Historical export links use their *persisted job result format*, avoiding accidental re-interpretation after republishing the quiz. New signed links require a successful verified private job and current role/ownership checks. Historical Firestore attempts, grading, upload paths and quiz links remain unchanged.
